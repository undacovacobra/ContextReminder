# ContextReminder v1.2 Reminder Access Design

## Goal
Make reminders faster to create and harder to miss by improving place selection, showing caller reminders below the call UI, and adding a home-screen quick-add widget.

## Location reminders
The Place trigger will search Android's Geocoder after a short typing debounce and show up to five resolved addresses below the field. A location reminder cannot be saved until the user taps one result. The chosen result is shown as `Using: <resolved address>` and supplies the exact latitude/longitude stored in the rule.

Geofence registration will become observable. Registration failures are returned to the add screen and displayed inline instead of silently closing the form. Successful registration is required before a new location reminder is treated as saved. Non-location reminders keep their current save behavior.

No Google Places API key or remote account is introduced in v1.2. Android's system Geocoder remains the source.

## Caller reminder overlay
Normal notifications remain the durable fallback. When an incoming-call rule fires and the app has Android's `SYSTEM_ALERT_WINDOW` authorization, ContextReminder also creates a temporary `TYPE_APPLICATION_OVERLAY` banner using the application WindowManager. The banner is positioned below the top call controls, is non-focusable, includes the reminder text and a dismiss control, and automatically disappears after 45 seconds.

Setup adds a `Show reminders over other apps` item that opens `Settings.ACTION_MANAGE_OVERLAY_PERMISSION` for this package and shows the current authorization state. If authorization is absent, the call reminder still produces the existing high-priority notification.

## Home-screen widget
A standard Android AppWidget exposes four buttons: Place, Person calls, Open app, Notification. Each button launches a translucent QuickAddActivity with the trigger preselected. The quick-add surface focuses the reminder text immediately and displays only fields needed by that trigger; advanced repeat/day/time controls are omitted. Saving closes QuickAddActivity and returns to the launcher.

The widget uses RemoteViews and AppWidgetProvider, with no network dependency. It does not attempt an editable text field inside the widget because Android RemoteViews do not support EditText for this use.

## Shared behavior
Rules continue to use the existing ReminderRule model and SharedPreferences storage. Existing v1.1 reminders remain compatible. App version becomes 1.2.0 / versionCode 3.

## Error handling
- Place search: empty/short queries show no results; geocoder errors show a concise search failure without saving.
- Place save: no selected result -> inline selection error.
- Geofence activation failure -> rule is rolled back and the add screen remains open with the failure reason.
- Overlay permission absent -> notification fallback only.
- Overlay WindowManager failure -> notification fallback remains; no call handling is blocked.
- Quick-add cancellation -> no rule is created.

## Verification
Core validation tests cover the requirement that a Place draft has a selected/resolved location. Android compilation verifies widget resources, manifest entries, Compose quick-add UI, overlay code, and geocoder integration. GitHub Actions must pass core tests and `assembleDebug` before the APK is delivered.
